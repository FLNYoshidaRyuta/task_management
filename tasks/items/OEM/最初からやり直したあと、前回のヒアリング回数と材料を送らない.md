## 概要

親Issue: #667

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

mypl_pro では、やり直し後もブラウザに前回の `hearing_question_count` と `material_ledger` が残っていた。サーバーはヒアリング状態だけを送り、回数が空のときは送らないことがあった。agent 側は回数が無いと上限に達したと扱い、「ヒアリングの上限に達しました」へ誤って落ちていた。本番の会話でも発生している。console-pro のやり直し（`resetModeLocalState`）は会話表示は消すが journey state を初期化していない。会話画面は `setUserJourneyState` をそのまま渡している。サーバー側の状態組み立てにも、回数を対で補う処理が無い。

対応する mypl_pro: Issue#1169、関連 agent-dev Issue#418。対照として console-pro にある開始案内へ1つ戻る（mypl_pro Issue#1096 / PR#1105）、コピー専用セッション廃棄（`abandonActiveCopyOnlyTaskSessions`）。

コメント 2026-11-04（#706〜#708 レビュー反映）で受け入れ条件を修正した。ヒアリング回数は、回数が空のときサーバーで補わず agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面 journey に回数があるときはその値をそのまま送る（旧条件の「空なら 0 を付ける」は撤回）。上限メッセージ「ヒアリングの上限に達しました」は agent-dev#421 本番以降出ない。回数 3 到達時は主役未決なら聞き直し質問を1回だけ、主役決定済みなら下書きへ。回数 3 から「最初からやり直す」→まとめ送信で、前回の回数・材料を送らず回数 0 から新規ヒアリングを始める。言い方はやり直し・モード開始後も残り、会話途中で初期設定から変えた場合は変更後が残る。

## やったこと

#706 → #707 → #708 のスタックでブラウザ確認中、受け入れ条件「上限表示のあとにやり直してまとめ入力…」をこのままでは確認できない不具合を2件特定した（ローカルセッション 49・50 の `SHOP_AGENT_CONVERSATION_LOGS` で agent 送信 body と checkpoint を突合）。

- 事象1: 確認カードで「入れたい内容が違う」等を選ぶと `hearing_question_count` が1戻ったように見える（次の送信では正しい回数）
- 事象2: 回数 3 到達後、回答を送っても「今回の投稿で一番伝えたいことは何ですか？」が繰り返され下書きに進めない
- 原因1: `MyplkunAgentService::withCurrentCheckpointRestoreSnapshot()`（`ChatPayloadBuilder` に同写し）が checkpoint の snapshot で `user_journey_state` と `current_state.agent_hearing_state_blob` を上書き。ヒアリング質問ターンでは checkpoint が保存されず、古いヒアリング状態が毎ターン送られ agent が同じ質問を繰り返す（`hearingStateBlobForResume()` の経路を素通り）
- 原因2: `ProComposedCheckpointV2Builder::journeyState()` が画面リクエストの journey を `array_replace` で agent 応答に重ね、agent の journey を捨てる。確認カード後の checkpoint に1ターン前の journey が保存される
- 対応方針（未実装）: 原因2は mypl_pro 同様 agent 応答優先に `journeyState()` を変更。原因1は `hearingStateBlobForResume()` が snapshot と異なる新しいヒアリング状態を返すターンでは `restore_snapshot` を付けず上位の値で送る

## 残りのやること

受け入れ条件（2026-11-04 反映後）を満たす実装と確認。

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- 回数が空のときはサーバーで補わず agent の台帳の数え直しに任せる。checkpoint や画面 journey に回数があるときはその値をそのまま送る
- やり直し後・モード開始後も言い方は残る（会話途中で初期設定から変えた場合は変更後が残る）
- ヒアリング中に上限メッセージ「ヒアリングの上限に達しました」が表示されない
- 回数 3 で主役の聞き直し質問が出たら1回だけ、次の回答で仮の下書きへ（同じ質問を繰り返さない）
- 回数 3 から「最初からやり直す」→まとめ送信で、前回の回数・材料を送らず回数 0 から新規ヒアリング（聞き直し質問やいきなり下書きにならない）
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない

コメント 2026-11-02 の対応方針: `journeyState()` を agent 応答優先に変更。checkpoint 後に会話が進んでいるターンでは `restore_snapshot` を付けない。

テスト手順（未了）: やり直し後送信 payload に前回の回数・材料が無い Vitest。ヒアリング状態のみで回数が空のときのサーバー挙動 PHPUnit（新条件に合わせる）。上限・やり直し・回数 3 からのやり直しの手動確認。
