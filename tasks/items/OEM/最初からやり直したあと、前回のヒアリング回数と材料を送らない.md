## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認を実施し、ヒアリング修正操作で次の2件の不具合を確認した（2026-11-02）。ローカルセッション49・50の会話ログ（`SHOP_AGENT_CONVERSATION_LOGS`）で agent への body と checkpoint を突き合わせた
- 事象1（確認カード修正で回数が1戻ったように見える）の原因として、`ProComposedCheckpointV2Builder::journeyState()` が画面の journey を `array_replace` で agent 応答に重ね、1ターン前の journey が checkpoint に保存されることを特定した
- 事象2（回数3到達後に「今回の投稿で一番伝えたいことは何ですか？」が繰り返され下書きに進めない）の原因として、`withCurrentCheckpointRestoreSnapshot()` / `ChatPayloadBuilder` が `restore_snapshot` 付きで古い checkpoint の journey とヒアリング状態を agent に送り続けることを特定した
- 対応方針を決めた。`journeyState()` は mypl_pro と同様 agent 応答を優先する。checkpoint より会話が進んでいるターンでは `restore_snapshot` を付けず上位の値で送る（2026-11-02）
- #706〜#708 のレビュー反映として受け入れ条件を修正した（2026-11-04）。ヒアリング回数のサーバー補完方針、上限表示後のやり直し、言い方の扱いを更新した

## 残りのやること

- `journeyState()` を agent 応答優先の形に直す（原因2）
- checkpoint の後に会話が進んでいるターンでは `restore_snapshot` を付けず上位の値で送る（原因1）
- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- 回数が空のときはサーバー側で補わず agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときはその値をそのまま送る
- ヒアリング中に、上限メッセージ「ヒアリングの上限に達しました」が表示されない
- 回数が3に達して主役の聞き直し質問が出たら、それは1回だけで、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）
- 回数が3に達した状態から「最初からやり直す」→内容をまとめて送ると、前回の回数と材料を送らずに、新しいヒアリングが回数0から始まる（聞き直し質問やいきなりの下書きにならない）
- やり直し後やモード開始後も言い方は残る。会話の途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
