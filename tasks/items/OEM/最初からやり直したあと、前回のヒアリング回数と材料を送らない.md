## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認をしたところ、ヒアリングの修正操作で次の2つが起きた。原因1は `withCurrentCheckpointRestoreSnapshot()`（`ChatPayloadBuilder` にも同じ写し）が `restore_snapshot` 付きで journey とヒアリング状態を古い checkpoint の snapshot で上書きしていたこと。原因2は `ProComposedCheckpointV2Builder::journeyState()` が agent 応答の journey より画面リクエストの journey を優先していたこと。
- 対応方針として、原因2は `journeyState()` を mypl_pro と同様 agent 応答優先にする。原因1は checkpoint より後に会話が進んでいるターンでは `restore_snapshot` を付けず上位の値で送る（mypl_pro と同じ）。巻き戻し・再開直後は今までどおり snapshot を付ける。
- 2026-11-04 に受け入れ条件をレビュー反映で修正した。回数が空のときはサーバーで 0 を補わず agent 台帳の数え直しに任せる（agent-dev#421）。agent-dev#421 以降「ヒアリングの上限に達しました」は出ない。回数3到達時の主役聞き直しは1回のみ。やり直し後は回数0から新ヒアリングを始める条件を追記した。

## 残りのやること

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- やり直し後やモード開始後も言い方は残る。会話の途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る
- 回数が空のときは、サーバー側で補わず agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときは、その値をそのまま送る
- ヒアリング中に、上限メッセージ「ヒアリングの上限に達しました」が表示されない
- 回数が 3 に達して主役の聞き直し質問が出たら、それは 1 回だけで、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）
- 回数が 3 に達した状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らずに、新しいヒアリングが回数 0 から始まる（聞き直し質問やいきなりの下書きにならない）
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
- 原因1・原因2の対応方針どおり `journeyState()` と `restore_snapshot` 付き送信経路を mypl_pro に合わせる
