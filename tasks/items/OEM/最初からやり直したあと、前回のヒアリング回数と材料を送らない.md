## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は console-pro にすでにあり、この Issue では再実装しない。

mypl_pro ではやり直し後もブラウザに前回の hearing_question_count と material_ledger が残り、サーバーは回数が空のとき送らず agent が上限到達と誤判定していた。console-pro の resetModeLocalState は journey state を初期化しておらず、サーバー側に回数を対で補う処理が無い。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認した。
- 事象1: 確認カードで修正を選ぶと hearing_question_count が1戻ったように見える（次の送信では正しい回数）。
- 事象2: 回数3到達後、回答を送っても同じヒアリング質問が繰り返され下書きに進めない。
- 原因1: withCurrentCheckpointRestoreSnapshot が restore_snapshot 付きで journey と hearing state を古い checkpoint で上書き（セッション49で5ターン同じ古い状態を送信）。
- 原因2: ProComposedCheckpointV2Builder::journeyState() が画面 journey を array_replace で重ね agent 応答を捨てる（セッション50 seq18）。
- mypl_pro は agent に restore_snapshot を送らず、journeyState は agent 応答を優先。

## 残りのやること

- 受け入れ条件: やり直し後の送信に前回の hearing_question_count と material_ledger が含まれない。やり直し後も user_preference_style は残る。ヒアリング状態送信時、回数が空なら0を対で送る（checkpoint に回数があるときは上書きしない）。上限表示のあとやり直してまとめ入力すると新しくヒアリングを続けられる。メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない。
- 対応方針: journeyState() を mypl_pro と同様 agent 応答優先にする。checkpoint 後に会話が進んでいるターンでは restore_snapshot を付けず上位の値で送る（巻き戻し・再開直後は従来どおり snapshot）。
- ヒアリング質問が続く間 checkpoint が保存されず回数が進まない点は mypl_pro と同様で残る。
