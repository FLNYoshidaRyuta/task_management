## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

mypl_pro では、やり直し後もブラウザに前回の `hearing_question_count` と `material_ledger` が残り、サーバーが回数を送らないと agent 側が上限到達と誤判定していた。console-pro の `resetModeLocalState` は journey state を初期化しておらず、サーバー側にも回数を対で補う処理が無い。

対応する mypl_pro: https://github.com/FutureLinkNetwork/mypl_pro/issues/1169 、関連 agent-dev: https://github.com/FutureLinkNetwork/agent-dev/issues/418 。console-pro に既にある開始案内へ1つ戻る（mypl_pro Issue#1096 / PR#1105）とコピー専用セッション廃棄（`abandonActiveCopyOnlyTaskSessions`）は再実装しない。

## やったこと

#706 → #707 → #708 のスタックでブラウザ確認中、ヒアリング修正操作で不具合2件を確認した。#673 の受け入れ条件「上限表示のあとにやり直してまとめ入力すると、新しくヒアリングを続けられる」はこのままでは確認できないため、同スタック上に修正2本を積む方針。

事象1: 確認カードで修正を選ぶと `hearing_question_count` が1戻ったように見える（次送信では正しい回数）。原因は `ProComposedCheckpointV2Builder::journeyState()` が `array_replace` で agent 応答 journey を捨て、1ターン前の journey が checkpoint に保存されること（セッション50・seq18で確認）。

事象2: 回数3到達後、回答を送っても同じ質問が繰り返され下書きに進めない。原因は `MyplkunAgentService::withCurrentCheckpointRestoreSnapshot()`（`ChatPayloadBuilder` に同写し）が snapshot で journey／ヒアリング状態を上書きし、質問継続中は古い checkpoint が毎ターン送られること（セッション49・回数3到達後5ターンで確認）。`hearingStateBlobForResume()` は新しい状態を拾うが、この経路は素通りしている。

対応方針: `journeyState()` を mypl_pro 同様 agent 応答優先にする。checkpoint 後に会話が進んでいるターン（`hearingStateBlobForResume()` が snapshot と異なる新状態を返す）は `restore_snapshot` を付けず上位値で送る。巻き戻し・再開直後（checkpoint が最新）は従来どおり snapshot を付ける。

## 残りのやること

受け入れ条件: やり直し次送信に前回の `hearing_question_count` と `material_ledger` が含まれない。やり直し後も `user_preference_style` は残る。ヒアリング状態送信ターンで回数が空なら 0 を対で送り、checkpoint に回数があるときは上書きしない。上限表示のあとやり直してまとめ入力すると新しくヒアリングを続けられる。メール／DM・口コミ「1つ前に戻る」の現行挙動は変えない。

上記2修正をスタックに積み、受け入れ条件と改修前再現手順（ヒアリング数回→やり直し→送信で前回回数・材料が残る／上限扱い）を確認する。テスト: やり直し後 payload に前回回数・材料が無い Vitest、ヒアリング状態のみで回数空のときサーバーが 0 同梱 PHPUnit、上限表示後のやり直し・まとめ入力の確認。

両方直しても、ヒアリング質問継続中は checkpoint 未保存のため回数が進まない点は mypl_pro 同様残る（ループにはならない）。
