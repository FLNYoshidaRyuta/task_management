## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

mypl_pro では、やり直し後もブラウザに前回の `hearing_question_count` と `material_ledger` が残っていた。サーバーはヒアリング状態だけを送り、回数が空のときは送らないことがあり、agent 側は上限到達と誤判定して「ヒアリングの上限に達しました」へ落ちていた。本番の会話でも発生している。console-pro のやり直し（`resetModeLocalState`）は会話表示は消すが journey state を初期化しておらず、会話画面は `setUserJourneyState` をそのまま渡している。サーバー側にも回数を対で補う処理が無い。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認中、ヒアリング修正操作で2不具合を確認した（修正カードで回数が1戻ったように見える／回数3到達後「今回の投稿で一番伝えたいことは何ですか？」が繰り返され下書きに進めない）。受け入れ条件「上限表示のあとにやり直してまとめ入力すると、新しくヒアリングを続けられる」はこのままでは確認できないため、同スタック上に修正を2本積む方針
- ローカル環境のセッション49・50の会話ログ（`SHOP_AGENT_CONVERSATION_LOGS`）で、agent に送った body と保存 checkpoint を突き合わせて調査した
- 原因1（事象2）：`MyplkunAgentService::withCurrentCheckpointRestoreSnapshot()`（`ChatPayloadBuilder` に同写し）が `restore_snapshot` 付きで `user_journey_state` と `current_state.agent_hearing_state_blob` を snapshot で上書きする。ヒアリング質問ターンでは checkpoint が保存されず、毎ターン古い journey／ヒアリング状態が agent に送られる。セッション49・回数3到達後5ターンで、agent は `subject_recovery_spent=true` を保存するがサーバーは古い `subject_recovery_spent=false` を送り続けた。`hearingStateBlobForResume()` は checkpoint より後の状態を拾うが、この経路は素通りしている
- 原因2（事象1）：`ProComposedCheckpointV2Builder::journeyState()` が画面リクエストの journey を `array_replace` で agent 応答に重ね、agent 応答を捨てる。セッション50・seq18 の checkpoint journey は seq11 の応答と一致し seq17 の応答（スロット filled、材料4件、回数0）と一致しなかった
- 対応方針：原因2は mypl_pro 同様 agent 応答の journey を優先する。原因1は `hearingStateBlobForResume()` が snapshot と違う新しいヒアリング状態を返すターンでは `restore_snapshot` を付けず上位の値で送る（巻き戻し・再開直後で checkpoint が最新のときは従来どおり snapshot を付ける）。mypl_pro は `restore_snapshot` を送らず上位の値で動いている
- 両方直しても、ヒアリング質問が続く間は checkpoint が保存されず回数が進まない点は mypl_pro とコード上同様で、上限判定が遅れることはあるがループにはならない、と整理した
- MYPL-4309 レビュー反映として、2026-11-04 に Issue 説明欄の受け入れ条件を修正した（ヒアリング回数の扱い、上限表示後のやり直し、言い方の扱い）

## 残りのやること

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- 回数が空のときは、サーバー側で補わず agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときは、その値をそのまま送る
- ヒアリング中に、上限メッセージ「ヒアリングの上限に達しました」が表示されない
- 回数が 3 に達して主役の聞き直し質問が出たら、それは 1 回だけで、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）
- 回数が 3 に達した状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らずに、新しいヒアリングが回数 0 から始まる（聞き直し質問やいきなりの下書きにならない）
- やり直し後やモード開始後も、言い方は残る。会話の途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
