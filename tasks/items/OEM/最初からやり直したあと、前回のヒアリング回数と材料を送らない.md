## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

mypl_pro では、やり直し後もブラウザに前回の `hearing_question_count` と `material_ledger` が残ることがあり、回数が空のとき agent が上限到達と誤判定していた。console-pro のやり直しは会話表示は消すが journey state を初期化しておらず、サーバー側にも回数を対で補う処理が無い。

## やったこと

- 2026-11-02: #706→#707→#708 のスタックでブラウザ確認中、ヒアリング修正操作で不具合 2 件を確認。原因として、(1) `restore_snapshot` 付きで journey／ヒアリング状態を checkpoint の snapshot で上書きし、質問が続く間 checkpoint が保存されないため agent に古い状態が送られ続ける、(2) `journeyState()` がリクエスト journey を `array_replace` で agent 応答に重ね agent 応答を捨てる、を整理し、mypl_pro に合わせた修正方針を記載。両方直しても、ヒアリング質問中は checkpoint が保存されず回数が進まない挙動は残る旨を記載。
- 2026-11-04: MYPL-4309 レビュー反映で受け入れ条件を改訂。ヒアリング回数は空のときサーバーで 0 を付けず agent 台帳の数え直しに任せる（agent-dev#421）。上限は agent-dev#421 以降「上限に達しました」メッセージは出ない前提に差し替え、回数 3 時の主役聞き直し 1 回とやり直し時の回数 0 開始など新条件を定義。`user_preference_style` はやり直し・モード開始後も残り、途中で初期設定チャットから変えた場合は変えた後の言い方が残る旨を明確化。

## 残りのやること

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- やり直し後やモード開始後も言い方は残る。会話途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る
- 回数が空のときはサーバー側で補わず agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときは、その値をそのまま送る
- ヒアリング中に、上限メッセージ「ヒアリングの上限に達しました」が表示されない
- 回数が 3 に達して主役の聞き直し質問が出たら、それは 1 回だけで、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）
- 回数が 3 に達した状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らず、新しいヒアリングが回数 0 から始まる（聞き直し質問やいきなりの下書きにならない）
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
- 2026-11-02 コメントの不具合 2 件に対する実装: `journeyState()` で agent 応答を優先する修正、checkpoint より会話が進んでいるターンでは `restore_snapshot` を付けず上位の値で送る修正
