## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

#706→#707→#708 のスタックでブラウザ確認したところ、「上限表示のあとにやり直してまとめ入力」の受け入れを妨げる不具合が2件あった。修正は同じスタックに2件積む。

事象1: 確認カードで修正を選ぶと `hearing_question_count` が1戻ったように見える。

事象2: 回数3到達後、同じ質問が繰り返され下書きに進めない。

原因1: `withCurrentCheckpointRestoreSnapshot` が journey／hearing を古い checkpoint で上書きする。

原因2: `ProComposedCheckpointV2Builder::journeyState` の `array_replace` が agent journey を捨てる。

## 残りのやること

- `journeyState` を mypl_pro と同様に直す
- `hearingStateBlobForResume` が異なるときは `restore_snapshot` をスキップする
- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- やり直し後も、店舗の言い方設定（`user_preference_style`）は残る
- ヒアリング状態を送るターンでは、回数が空なら 0 を付けて対で送る。checkpoint に回数があるときは上書きしない
- 上限表示のあとにやり直してまとめ入力すると、新しくヒアリングを続けられる
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
