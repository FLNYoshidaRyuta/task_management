## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。

#706〜#708 のスタック上での受け入れ条件は MYPL-4309 のレビュー（2026-11-04）に合わせて次のとおり差し替えた。ヒアリング回数は空のときサーバーで 0 を補わず agent の台帳の数え直しに任せ、checkpoint や画面の journey に回数があるときはその値をそのまま送る（agent-dev#421）。上限メッセージ「ヒアリングの上限に達しました」は出さない。回数 3 到達後の主役の聞き直し質問は 1 回だけとし、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）。回数 3 の状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らず回数 0 から新しいヒアリングを始める。やり直し後やモード開始後も言い方（`user_preference_style`）は残り、会話途中で初期設定チャットから変えた場合は変えたあとの言い方が残る。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認したところ、ヒアリングの修正操作で次の不具合を確認した（2026-11-02）。確認カードで修正を選ぶと `hearing_question_count` が 1 戻ったように見える。回数 3 到達後は「今回の投稿で一番伝えたいことは何ですか？」が繰り返され下書きに進めない。原因は `withCurrentCheckpointRestoreSnapshot` が snapshot で journey とヒアリング状態を上書きしていることと、`ProComposedCheckpointV2Builder::journeyState()` が agent の journey を画面の journey で上書きしていること。対応方針は journey を mypl_pro と同様 agent 優先にすることと、会話が checkpoint より進んでいるターンでは `restore_snapshot` を付けないこと。同スタックに修正 2 本を積む旨を記録した。
- MYPL-4309 レビューに沿って受け入れ条件を上記の新文言に更新した（2026-11-04）。

## 残りのやること

- スタックに積む 2 件の修正（`journeyState()` の agent 優先化、`restore_snapshot` 付与条件の見直し）を実装し、#673 の受け入れ条件をブラウザで確認できるようにする。
- 差し替え後の受け入れ条件（ヒアリング回数の送り方、回数 3 到達時の挙動、「最初からやり直す」後の送信、言い方の保持）を満たす。
