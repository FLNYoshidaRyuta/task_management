## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

mypl_pro では、やり直し後もブラウザに回数と材料が残り、上限を誤判定することがあった。console-pro の `resetModeLocalState` は journey を初期化しない等の差分がある。

## 残りのやること

受け入れ条件（2026-11-04 コメントで修正後）:

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- やり直し後も言い方は残る。途中で初期設定から言い方を変えた場合は、変えたあとの言い方が残る
- 回数が空のとき、サーバーで 0 を補わず agent の台帳数え直しに任せる。checkpoint や画面 journey に回数があるときはそのまま送る
- 上限メッセージ「ヒアリングの上限に達しました」は出ない
- 回数 3 で主役聞き直しの質問は 1 回だけ。次のターンで仮下書きへ進む（同じ質問を繰り返さない）
- 回数 3 から「最初からやり直す」→ まとめ送信で、新ヒアリングが回数 0 から始まる

2026-11-02 コメントの不具合と対応方針:

- 確認カード修正で回数が 1 戻ったように見える。回数 3 のあと同じ質問が繰り返される
- 原因は `restore_snapshot` の上書きと `journeyState` の `array_replace`
- `journeyState` を mypl_pro 同様 agent 優先にする。checkpoint より会話が進んでいるターンでは `restore_snapshot` を付けない
