## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認し、ヒアリング修正操作で不具合 2 件を特定した（2026-11-02）
- 原因 1：`MyplkunAgentService::withCurrentCheckpointRestoreSnapshot()` が `restore_snapshot` 付きで journey とヒアリング状態を古い checkpoint で上書きしており、回数 3 到達後に同じ質問がループした
- 原因 2：`ProComposedCheckpointV2Builder::journeyState()` が agent 応答より画面の journey を優先し、確認カード後に回数が 1 戻ったように見えた
- 対応方針：journeyState を mypl_pro と同様 agent 優先にし、会話が checkpoint より進んだターンでは `restore_snapshot` を付けない
- 受け入れ条件を MYPL-4309 レビュー反映で修正した（2026-11-04）

## 残りのやること

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- 回数が空のときはサーバーで 0 を補わず、agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときはその値をそのまま送る
- ヒアリング中に上限メッセージ「ヒアリングの上限に達しました」が表示されない（agent-dev#421 以降の挙動）
- 回数が 3 に達して主役の聞き直し質問が出たら 1 回だけとし、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）
- 回数が 3 の状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らず、新しいヒアリングが回数 0 から始まる
- やり直し後やモード開始後も言い方設定（`user_preference_style`）は残る。会話途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る
- `journeyState()` を agent 応答優先に直す（#707）
- 会話が checkpoint より進んだターンでは `restore_snapshot` を付けない（#708）
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
