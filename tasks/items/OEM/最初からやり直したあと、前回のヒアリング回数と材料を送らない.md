## 概要

親 Issue #667 の一部。ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは回数も対で送る。

mypl_pro ではやり直し後もブラウザに前回の `hearing_question_count` と `material_ledger` が残り、サーバーが回数を送らないと agent が上限到達と誤判定していた。対照は mypl_pro #1169 と agent-dev #418。console-pro の `resetModeLocalState` は会話表示は消すが journey state を初期化しておらず、会話画面は `setUserJourneyState` をそのまま渡している。

メール／DM と口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は console-pro にすでにある（mypl_pro #1096 / PR #1105、`abandonActiveCopyOnlyTaskSessions` など）。この Issue では再実装しない。

## やったこと

- 2026-11-02: #706→#707→#708 スタックのブラウザ確認で2件の不具合を特定。確認カード修正で回数が1戻ったように見える事象、回数3到達後に同じ質問が繰り返される事象。セッション49・50の会話ログで確認。
- 原因1: `MyplkunAgentService::withCurrentCheckpointRestoreSnapshot()` が checkpoint の古い journey/hearing を毎ターン送る（事象2）。
- 原因2: `ProComposedCheckpointV2Builder::journeyState()` が agent 応答より画面 journey を優先（事象1）。
- 対応方針を Issue コメントに記載（journeyState を mypl_pro 同様に、restore_snapshot は条件付き）。
- 2026-11-04: MYPL-4309 レビュー反映で受け入れ条件を Issue 上で修正。

## 残りのやること

- 「最初からやり直す」次送信に前回の hearing_question_count と material_ledger を含めない
- 回数が空のときはサーバーで補わず agent 台帳の数え直しに任せる。checkpoint/画面 journey に回数があるときはその値を送る
- 上限メッセージ「ヒアリングの上限に達しました」は出ない
- 回数3で主役聞き直し質問は1回だけ、次の回答で仮下書きへ（同じ質問を繰り返さない）
- 回数3から「最初からやり直す」→まとめ送信で前回回数・材料を送らず回数0から新ヒアリング
- やり直し・モード開始後も言い方は残る。途中で初期設定から言い方を変えた場合は変更後が残る
- メール/DM・口コミ「1つ前に戻る」の現行挙動は変えない
- 原因1・2のコード修正（journeyState 優先、restore_snapshot 付与条件）
- テスト手順に沿った Vitest/PHPUnit と上限後やり直しの確認
