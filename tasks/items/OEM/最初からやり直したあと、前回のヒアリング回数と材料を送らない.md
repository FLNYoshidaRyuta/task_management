## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

mypl_pro では、やり直し後もブラウザに前回の `hearing_question_count` と `material_ledger` が残っていた。サーバーはヒアリング状態だけを送り、回数が空のときは送らないことがあり、agent が上限到達と誤判定していた。console-pro のやり直し（`resetModeLocalState`）は journey state を初期化していない。

#706 → #707 → #708 のスタックでブラウザ確認中、ヒアリング修正操作で2件の不具合が見つかった。#673 の受け入れ条件「上限表示のあとにやり直してまとめ入力すると、新しくヒアリングを続けられる」をこのままでは確認できないため、同じスタック上に修正2本を積む方針（コメント 2026-11-02）。

## 残りのやること

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- やり直し後も、店舗の言い方設定（`user_preference_style`）は残る
- ヒアリング状態を送るターンでは、回数が空なら 0 を付けて対で送る。checkpoint に回数があるときは上書きしない
- 上限表示のあとにやり直してまとめ入力すると、新しくヒアリングを続けられる
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
- 事象1: 確認カードで修正を選ぶと `hearing_question_count` が1戻ったように見える → 原因2: `ProComposedCheckpointV2Builder::journeyState()` が agent 応答より画面 journey を優先 → mypl_pro と同様 agent 応答優先にする
- 事象2: 回数3到達後同じ質問が繰り返され下書きに進めない → 原因1: `withCurrentCheckpointRestoreSnapshot` が古い checkpoint で journey/ヒアリング状態を上書き → `hearingStateBlobForResume` が新しい状態を返すターンでは `restore_snapshot` を付けない（mypl_pro 同様）
- 両方直しても、ヒアリング質問が続く間 checkpoint が保存されず回数が進まない点は残る（ループにはならない）
