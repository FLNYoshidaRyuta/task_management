## 概要

ニュース作成ヒアリングで「最初からやり直す」後、次送信に前回の hearing_question_count と material_ledger が残らないようにする。ヒアリング状態送信時は回数も対で送る。

メール/DM・口コミ「1つ前に戻る」、コピー専用セッション廃棄は console-pro に既存。本 Issue では再実装しない。

mypl_pro ではやり直し後もブラウザに前回の hearing_question_count と material_ledger が残り、サーバーは回数空時送らず agent が上限到達と誤判定していた。console-pro の resetModeLocalState は journey state を初期化せず、サーバー側に回数を対で補う処理が無い。

## やったこと

- #706→#707→#708 スタックでブラウザ確認中、ヒアリング修正操作で2件の不具合を確認
- 事象1: 確認カードで修正を選ぶと hearing_question_count が1戻ったように見える（次送信では正しい回数）
- 事象2: 回数3到達後、回答を送っても同じ質問が繰り返され下書きに進めない
- セッション49・50の会話ログで agent body と checkpoint を突合
- 原因1: withCurrentCheckpointRestoreSnapshot が restore_snapshot 付きで user_journey_state と agent_hearing_state_blob を snapshot で上書き。質問継続中 checkpoint 未保存のため古い状態を毎ターン送信（mypl_pro は restore_snapshot を送らない）
- 原因2: ProComposedCheckpointV2Builder::journeyState() が画面 journey を array_replace で重ね agent 応答 journey を捨てる（mypl_pro は agent 応答優先）
- 対応方針: journeyState を mypl_pro 同様 agent 優先にする。checkpoint 後に会話が進んでいるターンは restore_snapshot を付けない
- 両方直してもヒアリング質問継続中は checkpoint 未保存で回数が進まない点は残る（mypl_pro も journey は checkpoint 最優先）

## 残りのやること

- 「最初からやり直す」次送信に前回の hearing_question_count と material_ledger が含まれない
- やり直し後も user_preference_style は残る
- ヒアリング状態送信ターンで回数空なら 0 を付けて対で送る。checkpoint に回数があるとき上書きしない
- 上限表示のあとやり直してまとめ入力すると新しくヒアリングを続けられる
- メール/DM・口コミ「1つ前に戻る」の現行挙動は変えない
- 上記2不具合の修正を #706→#707→#708 スタック上に積む
