## 概要

ニュース作成のヒアリングで「最初からやり直す」を押したあと、次の送信に前回のヒアリング回数と材料が残らないようにする。ヒアリング状態を送るときは、回数も必ず対で送る。

メール／DMと口コミ返信の「1つ前に戻る」、コピー専用セッションを画面入場で捨てる処理は、console-pro にすでにある。この Issue では再実装しない。

ヒアリング回数は、回数が空のときはサーバー側で補わず、agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときは、その値をそのまま送る。ヒアリング中に上限メッセージ「ヒアリングの上限に達しました」は表示されない。回数が 3 に達して主役の聞き直し質問が出たら、それは 1 回だけで、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）。回数が 3 に達した状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らずに、新しいヒアリングが回数 0 から始まる（聞き直し質問やいきなりの下書きにならない）。やり直し後やモード開始後も言い方は残る。会話の途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る。

## やったこと

- #706 → #707 → #708 のスタックでブラウザ確認をしたところ、次の 2 つが起きた。（1）確認カードで「入れたい内容が違う」などの修正を選ぶと、`hearing_question_count` が 1 戻ったように見える。次の送信では正しい回数になる。（2）回数が 3 に達したあとは、回答を送っても「今回の投稿で一番伝えたいことは何ですか？」が繰り返され、下書きに進めない。
- 原因として、`MyplkunAgentService::withCurrentCheckpointRestoreSnapshot()`（`ChatPayloadBuilder` にも同じ写しがある）が、`restore_snapshot` を付けたうえで `user_journey_state` と `current_state.agent_hearing_state_blob` を snapshot の値で上書きしている。checkpoint は、ヒアリング質問を返したターンでは保存されない。`ProComposedCheckpointV2Builder::journeyState()` が、agent の応答の journey に、画面がリクエストで送った journey を `array_replace` で重ねており、画面の journey はすべてのキーを持つので agent の応答がまるごと捨てられる。mypl_pro は agent に `restore_snapshot` を送らず、同じ関数では agent の応答の journey を常に優先し、リクエスト側はそれがないときの代わりにしか使っていない。

## 残りのやること

- 「最初からやり直す」の次の送信に、前回の `hearing_question_count` と `material_ledger` が含まれない
- 回数が空のときは、サーバー側で補わずに agent の台帳からの数え直しに任せる（agent-dev#421）。checkpoint や画面の journey に回数があるときは、その値をそのまま送る
- ヒアリング中に、上限メッセージ「ヒアリングの上限に達しました」が表示されない
- 回数が 3 に達して主役の聞き直し質問が出たら、それは 1 回だけで、次の回答で仮の下書きへ進む（同じ質問を繰り返さない）
- 回数が 3 に達した状態から「最初からやり直す」→ 内容をまとめて送ると、前回の回数と材料を送らずに、新しいヒアリングが回数 0 から始まる（聞き直し質問やいきなりの下書きにならない）
- やり直し後やモード開始後も、言い方は残る。会話の途中で初期設定チャットから言い方を変えた場合は、変えたあとの言い方が残る
- メール／DMと口コミ返信の「1つ前に戻る」の現行挙動は変えない
- `journeyState()` を mypl_pro と同じく、agent の応答を優先する形にする
- checkpoint の後に会話が進んでいる（`hearingStateBlobForResume()` が snapshot と違う新しいヒアリング状態を返す）ターンでは、`restore_snapshot` を付けずに上位の値で送る（mypl_pro と同じ）。巻き戻し・再開の直後（checkpoint が最新）は、今までどおり snapshot を付ける
